# Implementation Plan: List Saved Sets

**Branch**: `006-list-saved-sets` | **Date**: 2026-09-30 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/006-list-saved-sets/spec.md`

## Summary

Add `GET /v1/saved-sets` to the existing private saved-set resource. The operation uses the existing Cognito Bearer JWT authorizer and derives ownership only from the authenticated `sub`. It queries the authenticated user's saved-set partition, returns the existing public saved-set projection in two always-present arrays (`collection` and `wishlist`), and safely returns an error if retrieval fails. The implementation extends the existing handler-to-repository module and grants only DynamoDB query access in addition to its current write permissions.

## Technical Context

**Language/Version**: TypeScript 5.9 with strict mode; Node.js 24.x Lambda runtime  
**Primary Dependencies**: AWS SAM, API Gateway HTTP API JWT authorizer, AWS SDK v3 DynamoDB Document Client, AWS Lambda types, Zod 4, Vitest 4  
**Storage**: Existing DynamoDB `UserDataTable`; saved sets use `PK = USER#<sub>`, `SK = SAVED_SET#<setID>`, and `entityType = SAVED_SET`  
**Testing**: Vitest unit, handler integration, and OpenAPI/SAM contract tests; `npm run typecheck`, `npm run lint`, `npm test`, `sam validate --lint`, and `sam build`  
**Target Platform**: API Gateway HTTP API and ARM64 AWS Lambda deployed through SAM; iOS client  
**Project Type**: Serverless web service  
**Performance Goals**: At least 95% of valid requests return both lists within 2 seconds under normal development load  
**Constraints**: Versioned `/v1` route; Cognito Bearer JWT; ownership only from `sub`; no client user ID; no DynamoDB Scan; query all pages in the authenticated partition; least-privilege IAM; no sensitive logs or errors  
**Scale/Scope**: One GET operation on the existing saved-set Lambda and module; no new table, index, secret, environment, endpoint pagination, filtering, sorting, or deployment

**Structure Decision**: Extend the existing `saved-sets` resource rather than the physical collection module or a new Lambda. It already owns catalog snapshots stored under `SAVED_SET#<setID>` and supports both `collection` and `wishlist` destinations. This keeps read and write behavior for one resource together while adding only the query permission required for listing.
