# Implementation Plan: Eliminar set guardado

**Branch**: `007-delete-saved-set` | **Date**: 2026-09-30 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/007-delete-saved-set/spec.md`

## Summary

Add `DELETE /v1/saved-sets/{setID}` to the existing private saved-set resource. The API Gateway Cognito Bearer JWT authorizer and current authentication helper provide the owner only through the authenticated `sub`. The endpoint validates the positive numeric `setID`, conditionally deletes the exact `SAVED_SET` record within that owner's partition, confirms a successful deletion with the standard envelope, and returns an indistinguishable not-found response for a missing or inaccessible record. The change extends the existing handler-to-repository module, adds only the required DynamoDB delete permission, and introduces no new infrastructure resources.

## Technical Context

**Language/Version**: TypeScript 5.9 with strict mode; Node.js 24.x Lambda runtime  
**Primary Dependencies**: AWS SAM, API Gateway HTTP API JWT authorizer, AWS SDK v3 DynamoDB Document Client, AWS Lambda types, Zod 4, Vitest 4  
**Storage**: Existing DynamoDB `UserDataTable`; saved sets use `PK = USER#<sub>`, `SK = SAVED_SET#<setID>`, and `entityType = SAVED_SET`  
**Testing**: Vitest unit, handler integration, and OpenAPI/SAM contract tests; `npm run typecheck`, `npm run lint`, `npm test`, `sam validate --lint`, and `sam build`  
**Target Platform**: API Gateway HTTP API and ARM64 AWS Lambda deployed through SAM; iOS client  
**Project Type**: Serverless web service  
**Performance Goals**: At least 95% of authorized deletions confirm within 2 seconds under normal development load  
**Constraints**: Versioned `/v1` route; Cognito Bearer JWT; ownership only from `sub`; positive integer path identifier; no client user ID or request body; atomic conditional deletion; no DynamoDB Scan; least-privilege IAM; no sensitive logs or errors  
**Scale/Scope**: One DELETE operation on the existing saved-set Lambda and module; no new table, index, secret, environment, Lambda, soft-delete, batch deletion, pagination, filtering, sorting, or deployment

**Structure Decision**: Extend the existing `saved-sets` resource rather than the physical collection module or a new Lambda. It owns catalog snapshots stored under `SAVED_SET#<setID>` and already serves their GET and POST operations. This keeps all lifecycle operations for one resource together and adds only the `DeleteItem` permission it requires.
